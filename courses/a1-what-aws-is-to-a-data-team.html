What AWS is to a data team

AWS lists hundreds of services. A data team lives in about seven of them, and almost every decision a data leader signs off on is one of three questions: where the bytes live, who may touch them, and which meter is running while somebody reads them. Tonight we draw the map: what a Region is, which half of security is yours, the few services a data platform is built from, and the four meters that make up every bill.

Part 0

Where we start

Most AWS introductions start with the console and a list of icons. A data leader needs a different starting point: AWS is a place where storage and compute are rented separately, each by its own meter, behind one identity system that says no by default. Once that sentence is clear, the rest of the six leader sessions are details of it: S3 as the lake, IAM as the gate, compute versus serverless, the bill, and the one-page platform. The eight analyst sessions build the same pieces in Python on a laptop, against a local mock of the AWS API, on 100,000 real New York taxi trips.

Part 1 · covers Regions, Availability Zones and shared responsibility

Where your bytes physically are

5 min live

AWS describes its cloud as 124 Availability Zones within 39 Regions, with more announced. A Region is "a physical location in the world where we have multiple Availability Zones", and each Availability Zone is one or more separate data centres with their own power and networking. For a data team the practical meaning is short: you choose a Region, your data stays in it unless you move it, and most storage is copied across several Availability Zones inside it without you asking.

LiveRegion first, then everything else2 min▶

A Region is the first decision and the stickiest. Prices differ by Region, some services and models arrive in some Regions first, and data residency rules are usually written in terms of countries, which map onto Regions. Every price on these pages is quoted for one Region, us-east-1 in Northern Virginia, from the AWS Price List on 3 October 2026, and every page says so, because the same service can cost a different amount next door.

Inside a Region, S3 Standard and the other default storage classes are designed to survive the loss of a whole Availability Zone. Two classes are not: One Zone-IA and Express One Zone keep data in one zone. AWS's own wording is that One Zone-IA data "is not resilient to the physical loss of the Availability Zone". That is a fine trade for a copy you could rebuild, and a poor one for the only copy of anything.

LiveThe half of security that is yours2 min▶

AWS calls it the shared responsibility model: AWS is responsible for security "of" the cloud, and the customer for security "in" the cloud. AWS adds that the customer's share "will be determined by the AWS Cloud services that a customer selects". A managed service such as Athena takes more off your plate than a virtual machine you patch yourself, but no service takes away the two things that cause most incidents: who has access, and how the data is configured. That is why session 3 is about IAM and not about encryption algorithms.

Real world

The bucket that was "on AWS, so it was secure". A pattern repeated in public incident reports for a decade: a team assumes the provider handles security, a bucket policy is loosened for a quick share, and the data is readable from the internet. Nothing in AWS's half failed. The configuration sat in the customer's half, and nobody owned it. The fix is organisational before it is technical: a named owner for each bucket and a default that says no.

Part 2 · covers the services a data platform is built from

Storage, catalog, engines, a gate

6 min live

Strip a modern AWS data platform down and four kinds of thing remain. Storage that is cheap and nearly unlimited (S3). A catalog that says what the files mean (the Glue Data Catalog). Engines that read the files when someone asks a question (Athena, Redshift, Lambda, and for AI work, Bedrock). And one identity system around all of it that decides who may do what (IAM). The Well-Architected Data Analytics Lens puts the core idea in one line: "Decoupling storage from compute allows you to manage the cost of storage and compute separately".

LiveSeven services, one sentence each3 min▶

S3 stores objects, files with a key, in buckets. It is the lake. IAM holds users, roles and the JSON policies that say what they may do; anything not allowed is denied. Glue Data Catalog is "a centralized repository that stores metadata about your organization's data sets": table names, columns, and where the files are. Athena runs SQL straight on the files in S3 and bills by the bytes it reads. Redshift Serverless is the warehouse, billed by capacity per second while queries run. Lambda runs a function for up to 15 minutes when something happens, such as a file landing. Bedrock is managed access to foundation models, billed per token.

Everything else a data team meets, from EMR to Kinesis to SageMaker, is either a bigger engine, a stream, or a machine-learning workbench on the same storage. Streams have their own course, streaming data, and model tooling lives in DataOps.

Self-studyWhy decoupling is the whole architecture2 min▶

In an on-premises warehouse, storage and compute were bought together: more data meant a bigger machine. On AWS the files sit in S3 and any engine that is allowed can read them, so a team can query with Athena on Monday, load the same files into Redshift on Tuesday, and point a Lambda function at them on Wednesday, without copying anything. The price of that freedom is that each engine bills by its own meter, and a careless layout makes the reading meter run fast. The Analytics Lens was last updated on 22 December 2023, so treat it as a sound statement of principles rather than a current product list.

Part 3 · covers the four meters and the Free plan

Every bill runs on four meters

4 min live

A data leader does not need to memorise prices. They need to know which meter a decision turns on. Bytes stored, per GB-month. Bytes read, per terabyte scanned. Time, per GB-second or RPU-hour or vCPU-hour. Requests, per thousand or per million. Most surprises in a data platform bill come from the second and third, because they scale with how people work rather than with how much data there is.

LiveWhere the two numbers come from2 min▶

$23.55 is 1,024 GB at S3 Standard's first-tier price of $0.023 per GB-month. $15,000 is the same 1,024 GB read in full by Athena, at $5.00 per terabyte scanned, 100 times a day for 30 days. Both prices come from the AWS Price List for us-east-1, read on 3 October 2026. The second number is not a forecast for your team; it is what a common habit costs: raw CSV, no partitions, and a dashboard that reruns the whole table every few minutes. A CSV file is read whole, so even a question about a single week costs the full scan. Ask that one-week question, trips per pickup zone, of the same data stored as Parquet partitioned by day and it costs $88 a month. Analyst session 8 lets you change every part of the sentence and watch the number move.

Self-studyThe Free plan, as it stands today2 min▶

AWS changed its Free Tier for new accounts. Today a new account gets $100 in credits at once and can earn up to $100 more, "up to $200 over 6 months", and AWS says "You won't be charged unless you convert to a Paid plan". The account "closes on its own 6 months after you open it or when your credits run out". On the card question AWS's FAQ says "A payment method isn't required to sign up for most new customers", and also that in some cases it may ask for one to verify identity. Nothing in the leader track needs an account. The analyst track runs on a laptop and offers a real-account path on each page as an option, never a requirement. Terms like these change: re-check the page before you plan a workshop around them.

Real world

The proof of concept that cost more than the production plan. A team prices its new lake by storage, a few terabytes at cents per gigabyte, and the estimate looks tiny. In the first month the bill is many times larger, because analysts point a BI tool at raw CSV through Athena and every dashboard refresh reads every byte. Nobody did anything wrong by the storage estimate. The estimate measured the cheap meter. The scenario is constructed; the two prices are real.

Build-along

Your stack, on one AWS map

★ 22 min · everyone builds

No console and no account. A sheet of paper, the four layers from Part 2 and the four meters from Part 3. You place every tool your data team uses today onto the map, then mark which meter each one would run on if it moved to AWS. Session 6 turns this sheet into the one-page platform.

List what your team uses today, by layer. Where the files or tables live, what describes them, what runs queries and jobs, and how people get access. Write tool names, not aspirations. If one tool spans two layers, as most warehouses do, write it in both: that is exactly the coupling AWS separates.

Put an AWS building block next to each. Use only the seven services from Part 2. If nothing fits, write "not covered" rather than forcing a match; streaming and machine-learning workbenches have their own courses.

★ A finished row, in wordsLayer: Engines Today: BI dashboards on a SQL warehouse, refreshed every 15 minutes AWS block: Athena on S3 for ad hoc, Redshift Serverless for the dashboards Meter: Athena = bytes scanned; Redshift = RPU-hours while queries run Owner: analytics lead (dashboards), data platform lead (warehouse)

Tag each block with its meter. Bytes stored, bytes scanned, time, or requests. Circle any row where the meter scales with how often people click rather than how much data exists: those rows are next month's surprise.

Name an owner for every row. The person who answers when the meter jumps or the access is wrong. An empty owner cell is the most useful thing on the sheet, because it points at the half of shared responsibility nobody has picked up.

Write the one sentence. In your own numbers or in the course's: what it costs to store your largest table for a month, and what it would cost to scan it the way your dashboards do today. Session 5 checks your sentence against a real bill.

★ The sentence, with the course's numbersStoring 1 TB in S3 Standard: $23.55 a month. Scanning that 1 TB as CSV, 100 times a day, through Athena: $15,000 a month. A one-week question on partitioned Parquet: $88 a month. (us-east-1, AWS Price List, 3 October 2026)
✗ The map that becomes a migration plan nobody can pricemove everything to AWS use S3 for storage and figure out the rest later security is handled by the cloud provider

Price the reading, not the storing. When someone brings an AWS estimate, the first question is not "how many terabytes?" but "how many times a day is each terabyte read, by what, in what format?". That one question moves the conversation from the cheap meter to the one that decides the bill.

Homework

Before session 2

30 min
  1. Find out which Region your company's AWS work runs in, or would run in, and why. If the answer is "the default", note who could tell you whether a residency rule applies.
  2. Count the copies. For your most important dataset, find whether it lives in a storage class designed to survive the loss of an Availability Zone. If anyone uses One Zone storage, check that it is a copy you could rebuild.
  3. Find the reading meter. Pick one dashboard and ask how often it refreshes and how much data each refresh reads. Multiply. You now have the number session 5 starts from.
  4. Bring the one-page map. Session 2 fills in the storage row properly: buckets, prefixes, classes and lifecycle.
Check yourself

Three questions

Clear all three and leader session 1 gets stamped in your passport.

1 · A bucket in your account is readable from the internet because of a policy a colleague changed. Under the shared responsibility model, whose half is that in?

AWS secures the buildings, hardware and service software, security "of" the cloud. Access policies are configuration, security "in" the cloud, and they are the customer's to own.

2 · Why can a team query the same S3 files with Athena today and Redshift Serverless tomorrow without copying them?

Decoupling is the architectural idea the Analytics Lens names first. The cost of the freedom is that each engine bills separately, so the reading meter must be managed on purpose.

3 · A terabyte costs $23.55 a month to store in S3 Standard and $15,000 a month to scan as CSV 100 times a day through Athena. What is the right reading?

Both are real us-east-1 prices applied to one terabyte. The gap is the habit, not the service: a one-week question asked of partitioned Parquet costs $88 a month, because only seven daily folders and one column are read.
